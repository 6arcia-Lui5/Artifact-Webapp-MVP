# Museum keyword discovery

The integrated application adds keyword search to **Import → Find museum objects** for Met and Cleveland. Select a museum, enter a term, inspect and select objects, then choose **Add selected to research list**. Use Discoveries to Keep, Dismiss, or Undo the last decision. **Preview selected** remains a separate secondary action; the existing saved-import preview requires explicit confirmation before importing catalog records. Numeric-ID and file import remain available.

Search is `GET /api/research/discovery/search?provider=met|cleveland&q=coin%20pendant`, behind the existing approved-account gate. It writes no database rows. Responses have `provider`, `input`, `queries`, `items`, `partial`, `warnings`, `limits`, and `requests`. Each compact item includes provider/object identity, title, museum, thumbnail URL, source URL, retrieval timestamp, matching query variants, and `researchList`. That field is null for an unsaved object or `{id,decision,revision,previousDecision}` for this user's saved candidate. One owner/provider-filtered database read covers at most the 12 displayed IDs; another user's saved decisions are never included. Source matching means the museum returned the object; it is not a scholarly relevance judgment or an exact-text match claim.

## Query rules

Terms are at most 80 characters and four words. Two-word terms also try reversed word order; multiword terms try hyphenated and spaced forms. `jewelry` and `jewellery` are linked. Unicode letters are accepted, so users can enter museum terms in other languages directly. This feature does not provide automatic translation or claim a reviewed multilingual glossary.

Supported roots expand to the finite lists in `backend/src/research/discovery.ts`: `blunder*`, `erro*`, `forg*`, `garble*`, `imitate*`, `nonsens*`, `pseudo*`, `mistake*`. Other roots are rejected. `fake` is an ordinary term. These developer-reviewed defaults are open for Holly's review; they are not claimed exhaustive or client-approved. No raw asterisk is sent upstream. General spelling correction and all possible word permutations are not included.

## Request and cost limits

Each explicit search makes at most eight keyword queries, requests 12 matches per query, and displays at most 12 unique objects overall. A round-robin sample gives different query variants room. Search pages are not exhaustively downloaded. Limited samples, dropped details, failed queries, and deadline exhaustion are disclosed. Broad searches can miss relevant objects; no recall or precision improvement has been established.

Met uses `/public/collection/v1.1/search` with `offset=0&limit=12`, then fetches at most 12 distinct object-detail records. Cleveland uses `/api/artworks/` with `skip=0&limit=12` and a small `fields` projection, returning enough facts directly for discovery. There are at most **20 upstream requests per search**, at most **two concurrent requests**, an **18-second overall deadline**, and existing **8-second/1-MiB upstream response limits**. Successful queries remain available when other queries fail. No endpoint fallback hides failures. Total duration is subject to ordinary event-loop/network cancellation overhead; hosting must allow this deadline plus authentication/response overhead.

There is no AI inference, image copying, R2 usage, new paid service, scheduled crawler, or new dependency. Thumbnail URLs load from the existing museum image hosts. Repeated user searches repeat requests; there is no cross-request cache or global rate limiter. Existing approved-account checks remain in force. The integrated personal-decision lookup requires migration **003_discovery_decisions.sql** alongside 001 and 002. It introduces no further schema beyond the [discovery queue](feature-discovery-decisions.md).

Search results and query matches live only in the current page's memory and are lost on reload. **Add selected to research list** sends only provider and numeric IDs to the trusted existing candidate API; it waits for account synchronization, refetches current source summaries, and creates Not reviewed candidates without importing or auto-Keeping them. Repeated adds retain existing decisions and revisions. Saved results display **In research list**, **Kept**, or **Dismissed earlier**, with a link to review the decision. Saving has its own explicit request: at most 12 selected object requests under the adapter's two-request concurrency and 24-second retrieval deadline, with partial errors shown. Candidate storage remains capped at 1,000/user and 8 KiB of source text/candidate; no query-response archives or photographs are added.

Previewing selected results separately refetches current source facts through the existing importer and stores its normal preview job (30-day retention). Only a later explicit import creates catalog artifacts. Keep, Dismiss, and Undo never delete or modify catalog records. Museum-sourced multilingual expansion is available for saved catalog search; this external discovery endpoint still accepts directly entered terms without automatic translation.

## Evidence and limitations — November 4, 2026

Official documentation checked: [Met API](https://metmuseum.github.io/) and [Cleveland API](https://openaccess-api.clevelandart.org/). Met documentation identifies the new paginated v1.1 search endpoint and the October 1 retirement of the old search endpoint. Existing `/v1/objects/{id}` lookups remain documented. Neither documentation establishes reliable raw wildcard semantics.

Live read-only Node requests verified Met v1.1 `coin pendant` (HTTP 200, 120 reported matches). A full feature search returned 12 objects, four query variants, 16 upstream requests and a limited-sample warning in approximately 1.54 seconds. Example: object `465540`, **Coin/Pendant**, with a museum thumbnail and source record link. This is one connectivity smoke test, not a performance benchmark or accuracy evaluation.

Cleveland's first small request timed out at eight seconds. One subsequent feature search also had four timed-out query requests, returned zero objects after about 16 seconds, and disclosed incomplete results. No additional live retry was attempted. Cleveland success normalization/pagination is fixture-tested against its documented response shape; live success from this environment remains unverified. Do not interpret those failures as evidence that the museum contains no matches.

Original standalone-branch verification: both builds, frontend lint, 48 frontend unit tests and 135 backend tests passed; one existing PostgreSQL-dependent test was skipped. Seven new backend tests covered explicit variants, finite roots, cold repeated request budgets, per-query overflow, maximum concurrency, identity/provenance deduplication, no results, partial errors, cancellation/deadline, unsafe/malformed upstream data, account denial, repeated/unknown query rejection, and search-selected IDs entering the existing preview with zero artifact writes.

Integration verification on November 4: both builds and frontend lint passed; 144 backend tests and 54 frontend unit tests passed, with two opt-in database suites skipped in the default backend command. The dedicated real-PostgreSQL discovery suite separately passed **11 tests with none skipped**, using controlled museum responses and a uniquely generated disposable schema. Its new bridge scenario searches an unsaved object, adds the selected source identity, Keeps it, and observes the saved state on rediscovery. It also checks Dismissed state after a new server/pool, per-user decision isolation, repeated Add preserving the revision, Undo restoring Keep, and unchanged catalog-record counts. A focused unit test bounds annotation to one parameterized 12-ID owner/provider lookup; HTTP coverage checks remembered state and informative 503 when migration 003 is missing. Disposable schema removal is verified. These checks establish software behavior, not museum availability or research quality. Independent rendered desktop/mobile checks are owned by the parent development turn and are recorded separately.

## Run and review

Use the normal local setup in README. Run `npm run build --prefix backend`, `npm test --prefix backend`, `npm run build --prefix frontend`, `npm run lint --prefix frontend`, and `npm run test:unit --prefix frontend` (use `npm.cmd` on Windows if needed). Focused checks: `node --test backend/tests/museum-discovery.test.cjs` after backend build.

Sign in with an approved account, open Import, search `coin pendant`, expand Details and Queries tried, select an object, and create a preview. Verify that no artifact is created until the existing import confirmation is used. Check cancellation, an empty query result, a source error, narrower searches after a limited sample, and both museum choices. Retain existing import tests when changing this feature. For evaluation, have Holly judge representative known examples and compare missed examples and irrelevant results; passing software tests does not establish better research results.

Integrated review path in an isolated database: search → select an object → **Add selected to research list** → **Open research list** → Keep → Dismiss → repeat the museum search and observe **Dismissed earlier** → **Review decision** → **Undo last decision** → repeat the search and observe **Kept**. Confirm that another approved account sees its own independent state, and that the catalog count is unchanged throughout. **Preview selected** remains separately available; adding or Keeping an object does not approve an import.
